================================================================================
1. PROJECT OVERVIEW & ARCHITECTURE
================================================================================

This is a 3D top-down (isometric/Diablo-style) Action Roguelite RPG. The player
controls a single character from a fixed camera angle, fights enemies using
various weapon types (swords, bows, staves, daggers, lances, gloves, runes,
crossbows), uses class-based skills, and engages in life skills (farming, mining,
crafting). The game uses Synty modular 3D character models with Mixamo-retargeted
animations.

CORE ARCHITECTURE:
- Player is a CharacterBody3D (equivalent to Unity CharacterController)
- Component-based design: player.gd is the main hub, with child nodes for
  PlayerCombat, PlayerStats, PlayerInput, PlayerMovement, PlayerLifeSkill,
  PlayerUIManager, PlayerVisual
- Singletons (Autoloads): Global, ItemDB, SkillDB, CustomizationDB, PlayerHUD
- Enemies are also CharacterBody3D with AI state machines
- All databases are scene-based: items/skills are Sprite2D nodes with exported
  properties, built into dictionaries at runtime

PHYSICS:
- 3D physics with Jolt Physics engine
- Gravity: ProjectSettings default (9.8 m/s²)
- CharacterBody3D with move_and_slide() for all characters
- Area3D for hitboxes, hurtboxes, interaction zones
- NavigationAgent3D for pathfinding

================================================================================
4. COMBAT SYSTEM
================================================================================

──── Basic Attack Flow ────
1. Left-click triggers basic_attack
2. Check weapon type from ItemDB
3. For MELEE weapons (sword, long_sword, dagger, gloves, lance):
   - Call player.attack(false)
   - Combo system: Attack1 → Attack2 → Attack3 → loops
   - Combo resets if: timeout (1.0s) OR player takes damage
   - Hitbox activated via timer (30% of attack duration)
   - Hitbox deactivated at 80% of attack duration
   - Attack lunge (forward movement) for long_sword
4. For RANGED weapons (staff, long_bow, crossbow):
   - Call _fire_projectile(type, false)
   - Staff: fires magic projectile
   - Long bow: Load animation → Release animation → spawn arrow
   - Crossbow: fires arrow projectile
5. For RUNE weapon:
   - Fires magic projectile (3rd combo = double damage + larger)

──── Charge Attack (Right-click) ────
TAP WEAPONS (long_sword, sword, gloves, lance, rune, crossbow, dagger):
  - Single press: instant heavy attack
  - Cost: 30 EP (or 20 MP for rune)
  - Cooldown: 2.0s (crossbow: 1.0s)
  - Special behaviors per weapon:
    - long_sword charge: spin AoE attack (3.5m radius)
    - rune charge: mana burst AoE (knockback 10m)
    - sword charge: jumping slash with arc movement
    - gloves charge: 1.5x damage + camera shake
    - lance charge: dash + camera shake
    - crossbow charge: rapid-fire 5 bolts
    - dagger charge: throw 3 daggers in fan pattern

HOLD WEAPONS (staff, long_bow):
  - Hold right-click to charge (up to 2.0s)
  - Creates charge bar + visual orb (staff) or load anim (bow)
  - Release fires charged projectile
  - Staff: costs 30 MP, damage = magic_attack * (1.0 + charge_time)
  - Bow: costs 30 EP, damage = physical_attack * 2.0 * (1.0 + charge/2)

──── Damage Calculation (Player → Enemy) ────
1. Determine base damage:
   - Melee: physical_attack
   - Rune: magic_attack
   - Skill: formula per skill
2. Critical check: random < critical_chance
   - If crit: damage *= critical_damage_multiplier (1.5 + DEX*0.01)
3. Pass to enemy.take_damage(damage, position, elements, kb_force)
4. Enemy applies:
   - Element multiplier (from Global table)
   - Status effect multipliers (hunters_mark = 2x, etc.)
   - Knockback in direction away from attacker

──── Damage Calculation (Enemy → Player) ────
1. Base: enemy.damage
2. Subtract physical_defense (min 1 damage)
3. Holy Veil absorbs damage first (shield HP)
4. Status multipliers (vulnerable/sleep = 1.5x)
5. Element multiplier (attack element vs player def_element)
6. Elemental resistance reduction
7. If endure buff: no knockback
8. Knockback: 40 velocity units, decays at 800/sec = ~1 meter
9. Combo resets, attack canceled
10. Flash red 0.15s, play Damaged animation (max 0.5s)
11. Death at 0 HP

──── Hitbox System (SwordHitbox / sword_hitbox.gd) ────
- Area3D with manual_hit_radius fallback
- Uses hit_enemies list to prevent multi-hit same enemy
- clear_hit_list() + is_active flag
- _physics_process polls overlapping bodies each frame
- Manual radius fallback: checks distance from player center
- Weapon-specific radii:
    sword: 1.8m, long_sword: 2.5m, dagger: 1.4m,
    lance: 3.0m, gloves: 1.2m, rune: 0.0 (projectile), default: 1.5m
- Long_sword combo_step 1 (3rd hit): kb_force = 6.0, else 3.0
- Supports Hurtbox system on enemies (receive_hit method)

──── Projectile System ────
Player Projectile (player_projectile.gd):
  - direction: Vector3, damage: int, speed: float
  - lifetime: float, is_piercing: bool
  - atk_elements: Array

Arrow Projectile (arrow_projectile.gd):
  - Similar to player projectile but arrow-specific

Enemy Projectile (enemy_projectile.gd):
  - direction: Vector3, damage: int

──── AoE System (Generic, Diablo Immortal style) ────
Three reusable functions in player_combat.gd:

_aoe_instant_hit(origin, radius, damage, elements, kb_force, exclude_list):
  - Instant damage to all enemies in radius (XZ plane only, ignores Y)
  - Returns array of hit enemies

_aoe_delayed_hit(origin, radius, damage, delay, elements, kb_force):
  - Waits delay seconds, then does instant AoE

_aoe_tick_hit(origin_getter, radius, dmg_per_tick, tick_interval, duration, elements, kb_force):
  - Repeated AoE for duration, origin can move (follows player etc.)

5. ANIMATION SYSTEM
================================================================================

Uses AnimationTree with a BlendTree root containing:
  - BaseStateMachine (AnimationNodeStateMachine) — full body
  - UpperStateMachine (AnimationNodeStateMachine) — upper body overlay
  - Blend2 node — blends upper/lower body for locomotion with weapon poses
  - AttackTimeScale (TimeScale node) — controls attack animation speed

──── Dynamic Animation Lookup ────
Function get_anim_state(base_state) → String:
  1. Get current weapon_type from ItemDB (e.g., "long_sword")
  2. Build specific_state = weapon_type.replace("_","") + "_" + base_state
     Example: "longsword_Attack1"
  3. Check if state exists in BaseStateMachine or UpperStateMachine
  4. If not found, try lowercase version
  5. If still not found, fallback to base_state ("Attack1")

Function play_anim(base_state):
  1. Determine if full-body or blended:
     - Full body: Attack*, Skill*, Dash, Jump, or sword weapon type
     - Blended: Idle, Walk, Run (upper body gets weapon pose)
  2. For full body:
     - Set Blend2 amount to 0.0 (disable upper body override)
     - Play in BaseStateMachine
     - Use start() for Attack (force reset), travel() for others
  3. For blended locomotion:
     - Play Walk/Run/Idle in BaseStateMachine
     - Set Blend2 amount to 1.0
     - Play weapon-specific idle/walk in UpperStateMachine

──── Root Motion Stripping ────
On _ready(), ALL animations have their Hips/Root bone position tracks
modified: X and Z zeroed (in-place), Y preserved (prevent sinking).
This ensures characters don't drift from their collision body.

──── Animation Speed Control ────
- Attack speed: AttackTimeScale = attack_speed_multiplier * anim_speed_ratio
- anim_speed_ratio = actual_animation_length / base_attack_duration
- Walk/Run: animation_player.speed_scale = current_speed / stride_length
  (walk stride: 1.6, run stride: 4.8)
- Damage animation: if length > 0.5s, speed up to fit 0.5s

──── IK System ────
- SkeletonIK3D for left hand (IK_TanganKiri)
- Two-handed weapons: auto-finds LeftHand_Target (Marker3D) on active weapon
- Dynamically starts/stops based on weapon type
- Disabled during dash with staff

──── Head Look-At ────
- Only active when using long_bow AND attacking/aiming
- Smooth blend weight (0.0 to 1.0, speed 5.0)
- Finds "Head" bone, rotates toward mouse world position
- Uses skeleton local space quaternion slerp

6. WEAPON SYSTEM (Modular Scene)
================================================================================

Each weapon is a separate .tscn scene containing:
  - Root: Node3D
  - Visual: MeshInstance3D (3D model)
  - Hitbox: Area3D named "RightHandHitBox" or containing "Hitbox" in name
    - Script: sword_hitbox.gd
    - CollisionShape3D
  - (Optional) LeftHand_Target: Marker3D for IK grip

WEAPON TYPES (from ItemData):
  long_sword, sword, gloves, lance, staff, rune, long_bow, crossbow, dagger

WEAPON EQUIP FLOW:
  1. Global.equipment["main_weapon"] = item_id
  2. update_visual_equipment() called
  3. Iterates children of Slot_Weapon node
  4. Shows only the child whose name matches item_id (normalized, underscore-removed)
  5. For 2-handed weapons: activates left hand IK
  6. For 1-handed: stops IK

DUAL WIELD:
  - Only daggers support dual wield
  - Requires secondary_weapon slot also has dagger
  - Attack animation calls activate_weapon_hitbox() twice

  - endure (max 10): self-buff, prevents knockback
  - provoke (max 5): AoE taunt 5m radius, enemies forced to target player

──── APPRENTICE CLASS ────
Skills:

  - sonic_boom (max 5): frontal cone AoE
      → Triangle collision area, stuns enemies (2-5s based on level)
      → Element: "udara"
  - seismic_fissure (max 1): line of ground hazards
      → Spawns sequential hazard nodes from player to target
      → Each hazard damages + slows, element: "tanah"
  - holy_veil (max 1): damage absorption shield
      → Shield HP = magic_attack * 2.0 + skill_dmg
      → Visual: yellow transparent cylinder around player
  - hex (max 10): single-target curse debuff
      → Target gets "curse" status, enables Soul Drain combo
  - soul_drain (max 1): AoE drain on cursed enemies
      → Only hits enemies with curse status
      → Damage = magic_attack * 1.5, heals player 50% of damage

──── SCOUT CLASS ────
Skills:
  - dodge (passive): enables dodge/dash
  - evasion_mastery (max 10): evasion bonus
  - agility_mastery (max 10): agility bonus

      → Slow-motion effect (Engine.time_scale = 0.3) for final shot
  - arrow_rain (max 5): AoE rain of arrows at target position
      → Requires bow/crossbow, slow-motion spin animation
      → Spawns arrow_rain.tscn at target, deals damage over duration
  - haste (max 5): self-buff, doubles attack speed
  - mirage_strike (max 5): gives 3 charges of illusory strikes
  - poison_weapon (max 5): self-buff, adds poison to attacks
  - shadow_walk (max 5): stealth mode
      → Player becomes 50% transparent
      → Enemies lose aggro (chase radius = -1)
      → Broken by attacking or using certain skills
  - thief (max 1): steal loot from nearby enemy (<2m)
  - phantom_strike (max 5): teleport behind target + 2x damage
  - phantom_flurry (max 1): 10 rapid teleport strikes
      → Player invincible, teleports around target 10 times
      → 10% damage per hit, 0.1s interval

SKILL ACTIVATION FLOW:
  1. Press skill hotkey (1-8)
  2. Check: dead, casting, dashing, targeting, spinning, animating
  3. Check weapon requirements (bow skills need bow)
  4. Check cooldown, MP cost, EP cost
  5. Cancel current attack if attacking
  6. Determine skill type:
     - "instant" / "buff": execute immediately
     - "target_aoe" / "target_single" / "target_cone":
       → Enter targeting mode (Engine.time_scale = 0.2)
       → Show target indicator (circle/single/cone)
       → Left-click confirms, right-click cancels
  7. Start cast time (casting bar, blinking visual)
  8. After cast: deduct MP/EP, execute skill, start cooldown
  9. Cooldown reduced by spell_mastery level * 2%

SKILL DATA STRUCTURE (per skill in SkillDB):
  name, description, type, class_owner
  max_level, prerequisite_skill, prerequisite_level
  Per-level arrays (index 0 = level 1):
    ep_costs, mp_costs, cooldowns, cast_times,
    damages, effect_durations, crit_chances, aoe_radiuses, ranges

8. STAT & FORMULA SYSTEM
================================================================================

recalculate_stats() is called whenever equipment changes or level up.

CLASS BASE STATS: (see section 2)
TOTAL STAT = class_base + permanent_allocated + equipment_bonus

DERIVED FORMULAS:
  max_health = 50 + (total_vit * 10) + equip_max_hp
  max_mana = 20 + (total_int * 5) + equip_max_mp + elemental_mastery_mp_bonus
  max_energy = 50.0 + (total_str * 10.0)

  physical_defense = total_vit + equip_p_def + vitality_mastery_bonus
  magic_defense = floor(total_vit/2 + total_int/2) + equip_m_def + vitality_mastery_bonus

  walk_speed = (10.0 * 1000/3600) + (total_agi * 0.04) + (equip_aspd * 0.02)
  run_speed = walk_speed * 2.0

  attack_speed_multiplier = 1.0 + (total_agi * 0.05) + (equip_aspd * 0.01)
  energy_regen = 5.0 + (total_agi * 0.5)

  physical_attack:
    if bow/crossbow: 10 + (total_dex * 2) + equip_p_atk + weapon_mastery_bonus
    else: 10 + (total_str * 2) + equip_p_atk + weapon_mastery_bonus

  magic_attack = 10 + (total_int * 2) + equip_m_atk
  casting_speed = 1.0 + (total_dex * 0.05)
  critical_chance = total_luk * 1.0 + equip_critical  (percentage)
  critical_damage_multiplier = 1.5 + (total_dex * 0.01)
  accuracy = 1.0 + (total_dex * 0.05) + (equip_hit * 0.01)

MANA REGEN:
  If spell_mastery unlocked: regen spell_mastery_level MP per second (accumulates fractionally)

9. ENEMY AI SYSTEM
================================================================================

Three enemy types, all CharacterBody3D:

──── Melee Enemy (enemy.gd) ────
STATS: speed: 0.8, max_health: 50, damage: 10, element: "netral"
       chase_radius: 1.5, lose_interest_radius: 2.5, exp_reward: 10

AI STATE MACHINE (3 states):
  "idle":
    - If player in chase_radius and not shadow_walking → is_chasing = true
    - If chasing and distance > 2.0m → move toward player
    - If chasing and distance <= 2.0m → transition to "lunging"
    - If not chasing and far from spawn → return to spawn_position
    - Blind effect reduces chase_radius to 20%
  "lunging":
    - Move toward player at speed * 5.0
    - If within 1.2m → deal damage, transition to "returning"
    - After 0.25s timeout → transition to "returning"
  "returning":
    - Move away from player at speed * 2.5
    - After reaching 2.0m or 1.0s timeout → back to "idle"
    - Attack cooldown = 1.0 / attack_speed_multiplier

DAMAGE INTERRUPT: attack_cooldown = 5.0s on hit, resets lunge state

HP BAR: SubViewport (100x15) → Sprite3D billboard at Y=1.5

──── Ranged Enemy (ranged_enemy.gd) ────
STATS: speed: 0.7, max_health: 30, damage: 5
       chase_radius: 3.0, ideal_min_dist: 1.2, ideal_max_dist: 2.0

AI: Kiting behavior
  - If distance > ideal_max_dist → move toward player
  - If distance < ideal_min_dist → move AWAY from player (retreat)
  - If in ideal range → stop and shoot
  - Shoot every 2.0s (adjusted by attack speed)
  - Fires enemy_projectile.tscn

──── Boss Enemy (boss_enemy.gd) ────
STATS: speed: 0.6, max_health: 200, damage: 15
       chase_radius: 8.0, boss_name: string

AI: Two-state alternation
  "CHASE": Move toward player for 4 seconds
  "SHOOT": Stop and fire bullet hell (8 projectiles in circle pattern)
  Then back to CHASE for 4s, repeat

BOSS DEATH:
  - Opens buff_shop_menu (reward selection UI)
  - Drops 5 coins + 3 exp gems
  - Emits boss_died signal

COMMON ENEMY FEATURES:
  - Gravity: 20.0 m/s² (separate from project setting)
  - Loot drop: 50% chance coin, 100% exp_gem
  - Status effect support via StatusEffectManager
  - Element-based damage multipliers
  - Damage text: Label3D billboard, tween up + fade

13. STATUS EFFECT SYSTEM
================================================================================

StatusEffectManager (status_effect_manager.gd) — runtime child of player/enemy

STORAGE: active_effects: Dictionary<string, {duration, amount, tick_timer, source_pos, ...}>

EFFECTS LIST:
  Movement Restricting (can_move = false):

  Speed Modifiers:

    burn: 0.8x move speed, DoT

    haste: 2.0x attack speed

  DoT (Damage over Time, 1 tick/sec):
    poison: color (0.4, 1.0, 0.4)
    burn: color (1.0, 0.5, 0.2)
    bleed: color (1.0, 0.3, 0.3), 2x damage if target is moving
    curse: color (0.3, 0.0, 0.4), visual "💀" icon
    soul_drain: drains HP, heals source player

  Damage Modifiers:
    vulnerable: 1.5x damage taken
    hunters_mark: 2.0x damage taken, visual "🎯" icon

  Behavioral:
    fear: forced to run away from source_pos
    confuse: random direction change every 0.5-1.5s, color (0.8, 0.4, 0.8)
    paralyze: 0.5x attack speed, color (1.0, 1.0, 0.2)
    silence: cannot cast spells
    blind: chase_radius reduced to 20%, player gets dark overlay
    taunt: forced to attack player, visual "💢" icon

  Buffs:
    endure: no knockback
    shadow_walk: 50% transparency, enemies ignore player
    holy_veil: damage absorption shield, yellow cylinder visual
    poison_weapon: adds poison to attacks
    mirage_strike: extra illusory strikes
    haste: double attack speed

DAMAGE INTERACTION:
  - sleep broken by damage
  - freeze broken by damage → applies chill for 3s

VISUAL SYSTEM:
  - Each effect changes target modulate color
  - Shadow walk: 50% transparency on all meshes
  - Holy veil: CSGCylinder3D shield visual
  - Curse/Stun/Taunt/Mark: Label3D emoji billboard

IN UNITY: Use a Dictionary<string, StatusEffectData> on each character,
tick in Update(), apply visual effects via material property blocks.

16. LIFE SKILLS SYSTEM
================================================================================

──── Mining / Logging (ResourceNode) ────
resource_node.gd (Area3D):
  yield_item: string (e.g., "stone")
  required_tool: string (e.g., "pickaxe")
  required_cycles: int = 2 (attack animation loops)
  respawn_time: float = 10s
  yield_amount: int = 1
  
  Flow: interact → check tool → start_life_skill → attack animation loop
  → on_complete → add item to inventory → hide + respawn timer

──── Foraging (ForagingNode) ────
Similar to ResourceNode but for plants, no tool required typically.

──── Farming ────
FarmingZone (farming_zone.gd):
  - Player enters zone → interact → start_farming_targeting
  - Shows grid indicator at mouse position
  - Confirm → auto-walk to position → create CropPlot

CropPlot (crop_plot.gd):
  States: EMPTY → PLANTED → READY
  - EMPTY: interact → open seed menu → plant seed (3 animation cycles)
  - PLANTED: interact with watering_can → adds 60s of watered time
  - Growth progresses only while watered (watered_time_left > 0)
  - Max growth time: 120s (2 min debug)
  - READY: interact → harvest (+2 herb)
  
  Data stored in Global.farm_plots[plot_id]

──── Crafting ────
Recipes stored in Global.CRAFTING_RECIPES (auto-built from ItemDB)
Format: { "item_id": { "materials": {"mat_id": amount, ...}, "time": seconds } }

Flow: Open crafting menu → select recipe → check materials → start craft
  → timer runs in Global._process → finish → add item to inventory
  Recipes must be unlocked first (Global.unlocked_recipes)

──── Life Skill Animation Loop ────
start_life_skill(target, cycles, type):
  1. Face target direction
  2. Play Attack animation
  3. Wait base_attack_duration
  4. Increment progress
  5. Update progress bar
  6. If progress >= max → call target.on_complete(player)
  7. Else → loop
